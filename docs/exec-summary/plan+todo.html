The goal

Build the full single-user billing app on your PC. Records can be added by hand, or from a photo of a slip or bill that the AI reads. Every record is converted to THB, and the app shows totals and charts, with CSV export.

The app runs on your PC and over your home network, so your phone camera can be used.

Each step delivers something you can see working. The riskiest unknown, how well the AI reads Thai slips, is tested in step 2, before the rest of the app is built around it.

Rules the AI follows

Always

  • Work with one agent, one task at a time, in task order.
  • For each task: build it, run the automatic checks, check it in the running app, tick it off in the task list, then save a commit with nothing sensitive included.
  • Run a code review after every checkpoint, and fix or log its findings before the next phase.
  • Run a security review at Checkpoint D and when Phase 1 is complete, and a test review when Phase 1 is complete.
  • Hand off at a task boundary, about every 20-25 turns. The new session reads the newest handoff, then the task list, then the project status.

Asks you first

  • Real AI calls.
  • A new software package.
  • A database layout change after the first version.
  • Anything that exposes the app beyond the home network.

Never

  • Run several builder agents in parallel, because steps 6, 7 and 8 edit the same files and share one database layout.

How it is built

Pages read records straight from the database. Changes (add, edit, delete) go through separate entry points, so they can be tested without the screens and reused in Phase 2. One set of rules per kind of record is shared by the form, the entry points and the AI result reader.

Money is stored as whole numbers of the smallest unit, and rates as decimal text. Converting to THB is one function that rounds half up, run when you save. All file locations come from one setting, so Phase 2 only changes that setting.

Reading an image is one function. Tests use a fake one, and only a single script calls the real AI. The AI returns its answer in a fixed structure. Every field is optional, and missing ones are flagged.

Dates are stored in the Western calendar. Buddhist Era dates are converted only when the AI result is read.

Filters live in the page address, so the list, the dashboard and the CSV export share them, and links can be bookmarked.

Colours, text sizes and spacing are set once in step 5 and reused everywhere, so there is no restyle at the end. A commit is saved after every task that passes its checks.
